# 设计与故障分析

## 快照数量

默认保留 4 份 `verified` 自动快照。对 30 分钟周期而言，它通常提供退出最终状态以及约 30、60、90 分钟前的回退点。3 份在一份快照损坏时余量不足；第 5 份对本服务器的短时误操作恢复收益较低。未变化文件由硬链接复用，因此保留数量不是世界表观大小的简单倍数。

快照状态为 `pending`、`verified`、`failed`。复制、完整 SHA-256 清单完成后才持久化 `pending`；隔离 BDS 加载通过才转为 `verified`。隔离启动中任意 LevelDB corruption、repair、缺失 `.ldb` 或超时均转为 `failed`。失败快照会保留并在同一运行立即创建新的候选快照；自动轮换只删除超出数量的 `verified`，不会删除 `failed`、`pending`、旧 schema 或缺少归属元数据的目录。永久备份在自动目录之外，完全不属于此程序的删除范围。

## 状态机

| 当前状态 | 事件 | 动作 | 后续状态 |
| --- | --- | --- | --- |
| idle | 首位玩家连接 | 记录 30 分钟期限 | active |
| active | 其他玩家连接 | 不重置期限 | active |
| active | 玩家退出但仍有人在线 | 无 | active |
| active | 最后一位玩家退出 | 立即创建最终快照 | idle（成功） |
| active | 期限到达 | 创建周期快照 | active 或 idle |
| backing_up | 失败 | 5 分钟后重试 | active |

监听器重启时会读取 `/run` 中的状态并查询实际在线人数：

- 在线且原期限仍有效：继续原期限，不重新延长 30 分钟。
- 在线但期限已过：立即创建恢复快照。
- 无人但旧状态显示会话仍在进行：立即创建恢复快照，再进入 idle。
- 状态文件损坏：保守地创建恢复快照。

## 已处理的漏洞

1. **时间轮换导致空闲后无备份**：改为仅按完整快照数量轮换。
2. **每位玩家退出都备份**：退出事件后执行 `list`，只有在线人数变为 0 才触发。
3. **多人连续退出造成重复备份**：状态进入 backing_up/idle 后忽略同一批陈旧退出事件。
4. **周期备份期间最后一人退出**：周期快照结束查询到 0 人时，先持久化“必须补最终快照”再执行；崩溃重启会保守恢复。
5. **监听器重启重置计时**：期限写入原子状态文件并在重启后恢复。
6. **复制运行中 LevelDB**：仅在 BDS 明确返回可复制状态后执行 rsync。
7. **失败后世界长期停留在 hold**：`save resume` 位于上下文清理路径并要求日志确认。
8. **坏快照挤掉好快照**：文件清单完成后先标为 `pending`，在隔离 BDS 中实际加载且无 LevelDB repair/缺失迹象后才转为 `verified` 并轮换；验证失败保留且立即重试，旧 `verified` 始终受保护。
9. **并发任务互相覆盖**：使用非阻塞文件锁，只允许一个快照写入者。
10. **日志泄露身份信息**：只匹配连接事件类型，不转储原始玩家日志。
11. **安装校验失败留下半配置状态**：安装前保存精确目标文件和版本链接，任一步失败都会恢复旧文件并重新加载 systemd。
12. **旧版 journal 时间格式不兼容及运行态残留**：首次启动验证使用 journal cursor，不依赖时间解析；失败回滚会先停止本次启动的服务，再恢复安装前文件、启用状态和运行状态。
13. **人工 prune 与快照并发**：全部维护入口统一获取 `backup.lock`，锁被占用时明确拒绝。
14. **发布后维护失败触发重复备份**：以原子 rename 为提交点，后置维护失败只记录脱敏告警，并在启动或下次快照时修复。
15. **停止超时杀死 resume 清理**：固定布局限制关键超时上限，systemd 停止窗口提高至 600 秒。
16. **payload 目录存在但数据尚未持久化**：rsync 强制 `--fsync`，发布前同步 payload 目录、manifest 和仓库目录。
17. **伪造 manifest 被轮换删除**：只轮换带工具归属、受支持 schema、正确世界和 LevelDB 结构的快照；旧 schema 仅按严格结构兼容。
18. **系统时钟回拨导致轮换选错快照**：按 manifest 中的前驱链确定新旧顺序，目录时间名只用于无法归链的兼容项。
19. **未列入关键哈希的 payload 文件损坏**：新 schema 要求校验表精确覆盖 payload 中全部普通文件，并拒绝符号链接。
20. **配置与集成文件指向不同路径**：当前版本强制 `managed-v1` 固定布局，非匹配配置拒绝启动。
21. **子进程错误泄露路径**：日志只记录异常类别或退出码，不输出命令、世界路径和参数。
22. **全量校验延长 save hold**：在暂停保存前完成全部历史候选的哈希验证，hold 窗口只保留实时世界复制和目录同步。
23. **校验清单大于读取上限后仍被发布**：创建端和读取端共享 16 MiB 上限，超限会在原子发布前失败并清理临时目录。
24. **文件哈希正常但 LevelDB 恢复时 repair**：使用临时 BDS 运行时加载快照世界，日志中的 repair、corruption 和缺失 `.ldb` 都是硬失败，不把“自动修复后可启动”视为恢复成功。

## 剩余边界

- BDS 或主机突然断电时无法生成“退出快照”，只能恢复最近一次周期快照。
- `save hold` 期间玩家仍可继续活动；极短时间内发生的新变化可能属于下一份快照。
- 自动快照只有 4 份，不适合数天后才发现的长期腐坏；升级、加模组和大规模建筑前仍应创建手动里程碑备份。
- 硬链接快照不等于异地备份；磁盘或 VPS 整体损坏仍需云盘快照或异地副本。
- 自动快照不包含 BDS 二进制、systemd 和全局包目录，不应当作完整主机灾难恢复镜像。
- 隔离验证证明 BDS 在当前安装的运行时可加载该世界，但不能替代真实客户端对玩家背包、箱子、坐标、建筑和模组进度的验收；生产环境尚需首次受控演练确认 BDS 的实际日志措辞与端口隔离。
